# 趣分（资源分享平台）前端组件封装规划

基于当前项目现状梳理：`src/components/` 为空，仅有 `src/views/RegisterPage.vue` 一个页面，路由未配置，store 中已有 login/register，页面中仍使用 `alert()` 做校验提示。

项目处于起步阶段，重复代码最少，正是确定通用组件规范的最佳时机。

---

## 一、当前代码暴露的问题

`RegisterPage.vue` 中可直接观察到：

1. 5 个输入框结构完全重复（label + input + placeholder）
2. 校验失败使用 `alert('密码不一致')`，应改为输入框下方行内提示
3. 缺少统一的按钮组件，请求中没有 loading 态
4. 无布局组件，页面样式需重复编写

---

## 二、第一优先：当前页面立刻要用

| 组件 | 解决什么 | 对应现状 |
| --- | --- | --- |
| `BaseInput.vue` | 标签 + 输入框 + 行内错误提示 + 密码可见切换 | 5 个输入框结构重复；`alert('密码不一致')` 改为输入框下方红字 |
| `BaseButton.vue` | 类型 / 尺寸 / `loading` / `disabled` | 注册按钮需要请求中的 loading 态 |
| `Message` / `Toast` | 轻提示，替代 `alert()` | `alert('请同意协议')` 等 |
| `BaseModal.vue` | 确认弹窗 | 详见《消息弹窗组件实现指南》 |
| `BaseCheckbox.vue` | 同意协议勾选 | 与 `BaseInput` 统一表单风格 |

完成后，`RegisterPage.vue` 可从约 70 行硬编码缩减到 20 行左右，且不再使用 `alert`。

---

## 三、第二优先：资源分享平台核心业务组件

| 组件 | 用途 |
| --- | --- |
| `ResourceCard.vue` | 资源卡片：封面、标题、作者、下载量、标签、评分。首页 / 列表页 / 搜索结果通用 |
| `ResourceList.vue` | 列表容器 + 栅格布局 + 加载态 |
| `EmptyState.vue` | 无数据 / 搜索无结果的空状态 |
| `UploadDropzone.vue` | 上传：拖拽 + 点击选择 + 进度条 + 文件类型/大小校验（平台核心功能） |
| `CategoryTabs.vue` / `TagList.vue` | 资源分类切换、标签展示 |
| `SearchBar.vue` | 搜索框 + 联想 / 历史记录 |
| `Pagination.vue` | 列表分页（也可实现为无限滚动组件） |
| `UserAvatar.vue` / `AuthorInfo.vue` | 头像 + 用户名，卡片、评论区、导航栏通用 |

## 四、第三优先：布局与通用能力

| 组件 | 用途 |
| --- | --- |
| `AppHeader.vue` | Logo + 导航 + 搜索 + 登录后用户菜单 |
| `AppFooter.vue` | 页脚 |
| `BaseLayout.vue` | 整体布局骨架（header + main + footer） |
| `BaseLoading.vue` / `SkeletonCard.vue` | 加载占位，避免白屏 |
| `BaseDropdown.vue` | 用户菜单、排序下拉 |
| `ImagePreview.vue` | 图片资源预览（可选） |

> 登录态与权限控制建议做成**路由守卫 + store**，而不是组件。

---

## 五、目录结构建议

```
src/components/
├── base/        # 纯通用、不含业务：BaseInput / BaseButton / BaseModal / BaseLoading
└── business/    # 业务相关：ResourceCard / UploadDropzone / CategoryTabs
```

划分标准：**换一个项目还能不能用**。能用放 `base`，与"资源分享"绑定的放 `business`。

对应地：

```
src/
├── components/{base,business}/
├── types/            # 类型定义（已有 user.ts）
├── api/              # 请求层（已有）
├── stores/           # 状态管理（已有）
├── composables/      # 组合式函数（表单校验、上传等可复用逻辑）
└── views/            # 页面
```

## 六、什么时候该抽的判断原则

- 同一段结构出现 **2 次以上** → 抽
- 只出现 1 次但**未来必然复用**（如资源卡片）→ 提前抽
- 只出现 1 次且形态特殊 → 先不抽，等重复出现再重构

---

## 七、建议的实现顺序

1. `BaseInput.vue`（含行内校验提示）
2. `BaseButton.vue`
3. `Message` / `Toast`
4. `BaseModal.vue`
5. 用上述组件重构 `RegisterPage.vue`
6. 配置路由（`router/index.ts` 当前 routes 为空）
7. `ResourceCard.vue` 等业务组件

---

## 八、组件编写统一规范

1. 使用 `<script setup lang="ts">`，props 用 `defineProps` + `withDefaults`
2. 事件用 `defineEmits` 显式声明类型
3. 双向绑定优先 `defineModel`
4. 弹窗类组件必须 `<Teleport to="body">`
5. 样式统一 `scoped`，尺寸/颜色后续可抽 CSS 变量
6. 提交前会自动执行 `oxlint --fix`、`eslint --fix --cache`、`prettier --write`，遵循：不加分号、单引号、行宽 100
7. 提交信息使用约定式格式，例如：`feat: 新增 BaseInput 基础输入组件`
