# 消息弹窗组件实现指南

目标：封装一个可复用的弹窗组件，替代原生 `alert()` / `confirm()`，支持自定义内容、确认/取消回调，并支持 `await confirm()` 这种阻塞式写法。

技术栈：Vue 3.5 + TypeScript + Vite + Pinia（当前项目 `frontend` 已具备）。

---

## 一、最终想要的使用效果

先把目标写清楚，再倒推实现。

```ts
// 场景1：替代 alert()，只提示
await dialog.alert('操作成功')

// 场景2：替代 confirm()，等用户选择
const ok = await dialog.confirm('确定要删除这条资源吗？')
if (ok) {
  await ResourceAPI.remove(id)
}

// 场景3：内容复杂时，用插槽自定义
<BaseModal v-model="visible" title="上传资源">
  <ResourceForm @submit="visible = false" />
</BaseModal>
```

要做到这些，不能只靠插槽。

## 二、需要掌握的知识点

| 知识点 | 作用 | 为什么必须 |
| --- | --- | --- |
| `Teleport` | 把 DOM 渲染到 `body` 下 | 弹窗留在原位置会被父级 `overflow: hidden`、`z-index`、`transform` 影响，出现被裁剪、层级压不住的问题 |
| `Transition` | 进出场动画 | 直接 `v-if` 会瞬间闪现，体验差 |
| `defineModel` | `v-model` 绑定显示状态 | Vue 3.4+ 的写法，父组件 `v-model="visible"` 即可双向控制开关，无需手写 `update:modelValue` |
| 插槽 `slot` | 内容自定义 | 默认插槽放主体，具名插槽 `header` / `footer` 让标题和按钮区可替换 |
| `defineProps` + `withDefaults` | 类型安全的 props 与默认值 | TS 项目必须有类型；默认值避免每个调用点都传参 |
| `defineEmits` | 向父组件抛事件 | 用户点了确定/取消/关闭，父组件要能收到 |
| 组合式函数 / Pinia store | 命令式调用 | 让 `await dialog.confirm()` 成为可能，不必在每个页面写一遍标签 |
| Promise | 阻塞式交互 | 模拟 `confirm()` 的同步写法，代码线性可读 |
| 事件监听与清理 | ESC 关闭、滚动锁定 | 必须成对 `addEventListener` / `removeEventListener`，否则内存泄漏 |
| CSS 层级与遮罩 | 视觉与交互隔离 | `position: fixed` + `z-index` + 遮罩层，阻止穿透点击 |
| 无障碍（可选） | `role="dialog"`、`aria-*`、焦点管理 | 键盘用户可用，专业度更高 |

## 三、目录结构设计

```
frontend/src/
├── components/
│   └── BaseModal.vue        # 基础弹窗（纯 UI，不含业务）
├── stores/
│   └── dialog.ts            # 弹窗状态管理，提供 alert/confirm（Promise）
├── types/
│   └── modal.ts             # 弹窗相关类型
└── App.vue                  # 全局挂载一次 BaseModal
```

设计原则：**BaseModal 只管显示与事件，业务状态交给 store**。这样任何页面调用都不需要自己维护 `visible`。

## 四、分步实现

### 第 1 步：定义类型 `src/types/modal.ts`

```ts
export type ModalSize = 'small' | 'default' | 'large'

export interface ModalProps {
  title?: string
  size?: ModalSize
  maskClosable?: boolean
  showClose?: boolean
  confirmText?: string
  cancelText?: string
  confirmLoading?: boolean
  showConfirm?: boolean
  showCancel?: boolean
}
```

> 类型单独放 `src/types/`，与 `user.ts` 保持一致的分层约定。

### 第 2 步：实现 `src/components/BaseModal.vue`

```vue
<script setup lang="ts">
import { onBeforeUnmount, watch } from 'vue'
import type { ModalProps } from '@/types/modal'

// v-model 绑定的显示状态
const visible = defineModel<boolean>({ default: false })

const props = withDefaults(defineProps<ModalProps>(), {
  title: '提示',
  size: 'default',
  maskClosable: true,
  showClose: true,
  confirmText: '确定',
  cancelText: '取消',
  confirmLoading: false,
  showConfirm: true,
  showCancel: true
})

const emit = defineEmits<{
  (e: 'confirm'): void
  (e: 'cancel'): void
}>()

function close() {
  if (!visible.value) return
  visible.value = false
  emit('cancel')
}

function handleConfirm() {
  emit('confirm')
}

function handleMask() {
  if (props.maskClosable) close()
}

function handleKeydown(e: KeyboardEvent) {
  if (e.key === 'Escape' && visible.value) close()
}

// 打开时：锁定滚动 + 监听 ESC；关闭时：全部还原
watch(visible, isOpen => {
  if (isOpen) {
    document.body.style.overflow = 'hidden'
    document.addEventListener('keydown', handleKeydown)
  } else {
    document.body.style.overflow = ''
    document.removeEventListener('keydown', handleKeydown)
  }
})

onBeforeUnmount(() => {
  document.body.style.overflow = ''
  document.removeEventListener('keydown', handleKeydown)
})

const widthMap = { small: '320px', default: '420px', large: '640px' }
</script>

<template>
  <Teleport to="body">
    <Transition name="modal-fade">
      <div v-if="visible" class="modal-mask" @click="handleMask">
        <div
          class="modal"
          :class="`modal--${size}`"
          :style="{ width: widthMap[size] }"
          role="dialog"
          aria-modal="true"
          @click.stop
        >
          <header class="modal__header">
            <slot name="header">
              <span class="modal__title">{{ title }}</span>
            </slot>
            <button v-if="showClose" class="modal__close" aria-label="关闭" @click="close">×</button>
          </header>

          <main class="modal__body">
            <slot />
          </main>

          <footer v-if="showConfirm || showCancel" class="modal__footer">
            <slot name="footer">
              <button v-if="showCancel" class="btn" @click="close">{{ cancelText }}</button>
              <button
                v-if="showConfirm"
                class="btn btn--primary"
                :disabled="confirmLoading"
                @click="handleConfirm"
              >
                {{ confirmLoading ? '处理中...' : confirmText }}
              </button>
            </slot>
          </footer>
        </div>
      </div>
    </Transition>
  </Teleport>
</template>
```

**关键点回顾**

- `Teleport to="body"`：脱离父容器限制
- `@click.stop`：阻止内容区点击冒泡到遮罩导致误关闭
- `watch(visible)`：成对处理滚动锁定与 ESC 监听
- `onBeforeUnmount`：组件销毁时兜底清理，防止页面卡在 `overflow: hidden`
- 具名插槽都有默认内容：不传就用默认样式，传了就完全自定义

### 第 3 步：Pinia store 实现命令式调用 `src/stores/dialog.ts`

```ts
import { ref } from 'vue'
import { defineStore } from 'pinia'

export const useDialogStore = defineStore('dialog', () => {
  const visible = ref(false)
  const title = ref('提示')
  const content = ref('')
  const confirmText = ref('确定')
  const cancelText = ref('取消')
  const showCancel = ref(true)
  const confirmLoading = ref(false)
  const type = ref<'alert' | 'confirm'>('alert')

  let resolveFn: ((value: boolean) => void) | null = null

  function open(options: {
    content: string
    title?: string
    confirmText?: string
    cancelText?: string
    showCancel?: boolean
  }): Promise<boolean> {
    content.value = options.content
    title.value = options.title ?? '提示'
    confirmText.value = options.confirmText ?? '确定'
    cancelText.value = options.cancelText ?? '取消'
    showCancel.value = options.showCancel ?? true
    type.value = showCancel.value ? 'confirm' : 'alert'
    visible.value = true

    return new Promise<boolean>(resolve => {
      resolveFn = resolve
    })
  }

  function alert(content: string, title = '提示') {
    return open({ content, title, showCancel: false })
  }

  function confirm(content: string, title = '提示') {
    return open({ content, title, showCancel: true })
  }

  function settle(result: boolean) {
    visible.value = false
    resolveFn?.(result)
    resolveFn = null
  }

  function handleConfirm() {
    settle(true)
  }

  function handleCancel() {
    settle(false)
  }

  return {
    visible,
    title,
    content,
    confirmText,
    cancelText,
    showCancel,
    confirmLoading,
    type,
    alert,
    confirm,
    handleConfirm,
    handleCancel
  }
})
```

核心技巧：**把 `resolve` 存起来，等用户点击按钮时再调用**，这就是 Promise 化交互的本质。

### 第 4 步：在 `App.vue` 全局挂载一次

```vue
<script setup lang="ts">
import BaseModal from '@/components/BaseModal.vue'
import { useDialogStore } from '@/stores/dialog'

const dialog = useDialogStore()
</script>

<template>
  <RouterView />

  <BaseModal
    v-model="dialog.visible"
    :title="dialog.title"
    :confirm-text="dialog.confirmText"
    :cancel-text="dialog.cancelText"
    :show-cancel="dialog.showCancel"
    @confirm="dialog.handleConfirm"
    @cancel="dialog.handleCancel"
  >
    {{ dialog.content }}
  </BaseModal>
</template>
```

只需挂载一次，全站任何地方都能调用。

### 第 5 步：业务中使用

```vue
<script setup lang="ts">
import { useDialogStore } from '@/stores/dialog'

const dialog = useDialogStore()

async function handleDelete(id: number) {
  const ok = await dialog.confirm('删除后不可恢复，确定继续吗？', '危险操作')
  if (!ok) return
  await ResourceAPI.remove(id)
  await dialog.alert('删除成功')
}
</script>
```

对比原生写法的优势：样式统一、可异步、内容支持插槽、不会阻塞浏览器主线程。

## 五、进阶：不挂标签的纯命令式调用（可选）

如果不想在 `App.vue` 里写任何标签，可以用 `createVNode` + `render` 动态挂载：

```ts
import { createVNode, render } from 'vue'
import BaseModal from '@/components/BaseModal.vue'

export function showModal(options: ModalOptions) {
  const container = document.createElement('div')
  const vnode = createVNode(BaseModal, {
    modelValue: true,
    ...options,
    'onUpdate:modelValue': (v: boolean) => {
      if (!v) {
        render(null, container)
        container.remove()
      }
    }
  })
  render(vnode, container)
  document.body.appendChild(container)
}
```

要点：关闭时必须 `render(null, container)` 并移除容器，否则 DOM 与组件实例泄漏。

> 建议先用第 3、4 步的 Pinia 方案（简单、可调试），等熟悉后再考虑此方案。

## 六、常见坑与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 弹窗被父容器裁剪 | 没用 `Teleport` | 用 `<Teleport to="body">` |
| 点内容区弹窗就关闭 | 事件冒泡到遮罩 | 内容区加 `@click.stop` |
| 关闭后页面无法滚动 | 滚动锁定未还原 | `watch` 与 `onBeforeUnmount` 双向兜底 |
| 连续调用只弹一次 | `resolve` 被覆盖 | 调用前先 `settle(false)` 或禁止并发 |
| 层级压不住其他元素 | `z-index` 不够 | 统一弹窗 `z-index`（如 1000），并避免局部创建层叠上下文 |
| `alert` 后代码继续往下跑 | 没 `await` | 必须 `await dialog.alert(...)` |
| TS 报 props 类型错 | 未用 `withDefaults` | 为每个可选 prop 提供默认值 |
